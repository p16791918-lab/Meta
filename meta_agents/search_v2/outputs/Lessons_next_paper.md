# 다음 논문 대비 체크리스트 — 이번 프로젝트 lessons learned

*Racial and Ethnic Differences in Breast Cancer Incidence (SR/MA) 작업에서 실제로 걸린 지점 정리. 일반론이 아니라 "이번에 발생한 일 → 다음 대비".*

## 우선순위 요약 (가장 값비쌌던 셋)
- 어조를 처음부터 타깃/지도교수 논문 강도에 맞추지 않아 반복 수정.
- "narrative synthesis"처럼 **말만 하고 실물이 없던** 항목.
- 피드백이 확정되기 전에 하류 산출물(표·그림·서지)에 과투자 → 대량 재작업.

이 셋만 초반에 잡으면 재작업이 크게 줄어든다.

---

## 1. 어조 — 가장 반복적으로 걸린 문제
이번에: 단정 표현, 절대어(every/all), 수사어(mask/conceal/dissolve), Background에 결론을 미리 전제, 같은 제언 3회 반복(surveillance), "will require"·"is needed" 같은 필연조.

다음엔:
- 설득이 아니라 기술. Results는 수치만, Discussion은 "~하면 더 정확할 것이다(would)" 수준.
- Background에 결론을 심지 말 것 — 배경은 사실·간극만, 판단은 Results로.
- 같은 결론은 한 번만 (Abstract·Discussion·요약 중복 금지).
- 전향 문장은 would/may benefit from; must/will require/should overhaul 금지.
- 타깃/지도교수 논문의 어조에 캘리브레이션 (예: 이번 지도교수 논문은 "regulatory conclusions 지양, proportionate/balanced").

## 2. "말한 것"과 "실제 있는 것"의 불일치
이번에: "115편이 narrative synthesis에 기여"라고 써놓고 그 섹션이 없었음. "Supplementary Table 2에 목록"이라 했는데 식별자가 없었음.

다음엔: 주장하는 방법·섹션·분석은 반드시 그 실물이 문서에 존재해야. 마지막에 claim ↔ deliverable 전수 대조.

## 3. 데이터 정합성 — 단일 원천
이번에: 파생 IRR 오류(TNBC 분모를 12.7 대신 139.5, Hispanic 근사분모 ~143). Table 1과 forest가 서로 다른 코드 경로로 계산. main↔sensitivity 불일치.

다음엔:
- 하나의 master extraction dataset만. 모든 표·그림은 여기서 재생성.
- 저자 계산값은 자기 입력값에서 재계산 검증(계산식·분모·표준화·CI 산출법).
- 동일 값을 두 코드가 따로 계산하지 말 것. 전 값이 원장으로 추적되는 자동 cross-check를 처음부터.

## 4. 용어·표기 통일
이번에: Filipina/Filipino, Hawaii/Hawai'i, API/AANHPI, White/NHW 혼용.

다음엔: 표시 라벨을 한 곳(labels 매핑)에서 통제. 원 논문 정의대로 통일. 최종 전 변형 표기 전수 검색.

## 5. 작업 흔적이 원고에 새는 것
이번에: "2nd-round revision", "earlier draft" 같은 수정이력·스캐폴딩 노트가 초안 본문에 섞임.

다음엔: process 노트 ≠ 논문 본문. 논문은 "무엇을 했는가"만. TODO·이력은 별도 체크리스트 파일로.

## 6. 피드백을 대전제로, 최신이 우선
이번에: 1차 결정(NOS·GRADE·pooling)이 2차에서 뒤집혀 하위 산출물 대량 재작업.

다음엔: 피드백이 최우선, 충돌 시 최신 라운드가 우선. 피드백 확정 전 하류(표·그림·서지)에 과투자 금지.

## 7. AI가 할 수 있는 것 vs 저자 몫
이번에: PROSPERO 등록, 2인 독립 reviewer 실제 수행, 환경 차단(NCBI)으로 서지 자동완성 불가 — 혼동 여지.

다음엔: 저자만 할 수 있는 것(등록·실제 이중검토)과 자동화 가능한 것을 처음부터 분리. 환경 제약은 정직히 밝히고 핸드오프 도구(PMID 블록·스크립트) 제공.

## 8. 프레이밍이 실제 분석과 일치하는가
이번에: 대표값 방식을 pooled처럼 오해할 소지. 제목은 "Meta-analysis"인데 실제로 pooling을 안 함(잔여 불일치 — 제목을 "Systematic Review"로 조정할지 확인 필요).

다음엔: 한 것과 표현을 일치. 제목·초록·방법이 실제 분석과 어긋나지 않는지 최종 점검.

## 9. 인용·근거
이번에: 거대 블록 인용, 포함 연구 전체가 개별 참조 안 됨, 서지 미완성.

다음엔: 모든 정량 주장은 직접 읽은/추출한 특정 출처에 앵커. 블록 인용 지양. 포함 연구 전체를 식별자와 함께 목록화. 없는 수치·서지는 지어내지 말고 flag.

## 10. 검증은 자동+수동 둘 다
이번에: 자동 검수(1인칭·절대어·산술 163=48+115)로 많이 잡았지만, narrative synthesis 부재·Background 전제·어조는 사람이 잡음.

다음엔: 자동 레드플래그 스크립트 + 전문 통독 병행. 자동화는 표면(단어)만, 논리·전제·반복은 통독으로.

## 11. 요구되지 않은 항목의 자발적 추가
이번에: funnel plot/Egger(출판편향)는 두 피드백에 없었으나 SR 관행상 자발적으로 넣음(안 한 이유를 정당화). 적절하나, 넣을지 여부는 분석 성격(비pooling)에 맞춰 판단해야.

다음엔: 관행 항목은 넣되, 실제 분석과 맞는지 확인하고 "왜 안 했는지"를 정당화. 불필요하면 과감히 생략.

## 12. 제약을 실시간으로 추적
이번에: 초록 300단어 한도를 편집할 때마다 초과 → 반복 트림.

다음엔: 단어수·저널 포맷(구조형/비구조형)·그림 수 등 제약을 편집 중 계속 확인. 타깃 저널을 초반에 확정.
